# Общие задания и единственный учитель

Сайт по-прежнему работает на GitHub Pages. Текст заданий хранится в Supabase,
вход проверяет Supabase Auth, право записи ограничивают политики PostgreSQL (RLS).
Ученикам регистрация не нужна. Задания доступны всем посетителям сайта;
отметки выполнения остаются на устройстве ученика и учителю не отправляются.

## Первоначальное подключение

1. В [Supabase Dashboard](https://supabase.com/dashboard) создайте отдельный проект.
   Выберите подходящий регион и тариф в своём аккаунте. Пароль базы храните у себя.
2. Откройте SQL Editor и выполните
   `supabase/migrations/202609160001_teacher_homework.sql` целиком, один раз.
3. В Authentication отключите **Allow new users to sign up**.
   Оставьте вход по email/паролю; анонимную авторизацию и социальные провайдеры не включайте.
4. В Authentication → Users → Add user → Create new user создайте
   единственного учителя с его email и сильным уникальным паролем.
   Подтвердите email при создании (Auto Confirm User). Пароль передайте учителю
   лично; в GitHub, файлы сайта и чат его не вставляйте.
5. Скопируйте UID созданного пользователя. В SQL Editor выполните запрос ниже,
   заменив `TEACHER_USER_UUID` на UID. Email не записывается в публичный код.

   ```sql
   insert into school_private.teacher (slot, user_id)
   values (1, 'TEACHER_USER_UUID'::uuid)
   on conflict (slot) do update set user_id = excluded.user_id;
   ```

6. В Connect / Settings → API Keys скопируйте **Project URL** и
   **Publishable key** (`sb_publishable_…`) в `homework-config.js`.
   Это публичные параметры. Secret key, service_role, пароль базы и пароль учителя
   в сайт не добавляются. Современный publishable key передаётся в заголовке apikey,
   токен вошедшего учителя — отдельно в Authorization.
7. Опубликуйте сайт. При следующих изменениях конфигурации увеличивайте `?v=N`
   в `index.html`, версию и пути в `service-worker.js`, чтобы обновились установленные приложения.

До подключения `homework-config.js` форма входа скрыта, раздел сообщает,
что общие задания пока не подключены. Это не готовый общий доступ.

## Проверка после подключения

- В обычном браузере откройте «Вход для учителя», войдите и опубликуйте
  тестовое задание с предметом, текстом и датой сдачи.
- В приватном окне откройте сайт: задание видно без входа, кнопок изменения нет.
- Отметьте его выполненным: отметка не должна появиться в другом браузере.
- Измените текст учителем, затем нажмите «Обновить» в приватном окне:
  новый текст виден, прежняя отметка выполнения сброшена.
- Проверьте удаление. При отключении сети ученику показывается последняя
  загруженная копия с датой; учитель не получает ложного сообщения об успешном сохранении.
- Открытые страницы проверяют новые задания каждую минуту и при возврате во вкладку.
  Офлайн-устройство увидит изменения и удаления после подключения к сети.

## Как устроен доступ

`school_private.teacher` недоступна через браузер. Первичный ключ `slot`, ограниченный
значением 1, допускает только одну запись. Только владелец проекта через SQL Editor
может назначить или заменить учителя. Даже другой авторизованный пользователь не
получает права записи. Проверка работает в базе, независимо от кнопок интерфейса.
Это один аккаунт учителя, а не запрет на несколько его устройств. Передача пароля
передаёт доступ, поэтому пароль знает только учитель.

Вход хранится лишь в памяти вкладки. После перезагрузки страницы или истечения
серверного токена нужно войти снова. Пароль не сохраняется приложением. Ошибка
входа или записи оставляет текст в форме до закрытия страницы.

Чтобы сменить учителя, создайте новый аккаунт и повторите запрос назначения выше.
Предыдущий аккаунт сразу потеряет право изменять задания, даже с ещё действующим токеном.
Чтобы временно отозвать доступ, удалите единственную запись из `school_private.teacher`
в SQL Editor. Восстановление пароля выполняет владелец проекта в Supabase;
самостоятельное восстановление через почту в этой версии не реализовано.

## Фотографии и новый интерфейс (19 сентября 2026)

После основной миграции выполните в SQL Editor файл
`supabase/migrations/202609190001_homework_photos.sql` один раз. Он добавляет
`assignments.photo_paths` и публичный bucket `homework-photos`. Старые задания,
назначение учителя и пароли не меняются. После этого публикуйте клиент v4.

Главный экран открывает расписание; задания доступны отдельной вкладкой со
счётчиком невыполненных актуальных заданий на этом устройстве. Выполненные задания
и прошедшие сроки сворачиваются отдельно. «Учителю» в шапке открывает вход.
После входа нажмите «Добавить задание», заполните предмет, дату, короткое описание
и при необходимости выберите фотографии.

- До 4 фото в задании. Исходные JPEG/PNG/WebP — до 20 МБ; HEIC/HEIF только если
  браузер умеет их декодировать. В противном случае интерфейс предложит JPEG.
- Перед передачей изображения заново кодируются в JPEG с длинной стороной
  не более 2400 пикселей, без исходных EXIF/GPS. Сервер ограничивает JPEG размером 5 МБ.
- Фото общедоступны по URL, как и задания. Не публикуйте личные данные и фото детей.
  Удаление с сайта не отзывает уже скачанные пользователями копии.
- Загружать и удалять неиспользуемые фото может только назначенный учитель.
  Перезапись существующего URL запрещена. Пока фото связано с заданием, удалить
  его из Storage нельзя: сначала нужно сохранить задание без этой фотографии.
- При сбое загрузки форма и готовые фото остаются во вкладке; повторная отправка
  использует уже загруженные вложения. При отмене, замене фото или удалении задания
  приложение пытается очистить неиспользуемые объекты через Storage API.
- Если вкладку закрыли в момент запроса или очистка не удалась, возможны
  неиспользуемые объекты. Автоматического фонового удаления нет. Их можно проверить
  в Supabase Storage, сопоставив имена с `assignments.photo_paths`, и удалить через
  Storage API/панель (не прямым DELETE из `storage.objects`).
- Офлайн сохраняется текст и личные отметки; доступность фотографий без интернета
  не гарантируется. Для чтения фото предусмотрены увеличение и открытие отдельно.

Откат интерфейса: вернуть статические файлы предыдущего релиза, присвоив им новый
номер кэша (не использовать повторно v3/v4). Аддитивную миграцию и bucket оставить:
старый клиент продолжает работать, а фото и существующие задания не теряются.
Откат нужен, если перестали открываться расписание, задания или вход учителя.

## Локальные проверки

```sh
npm ci
npm test
```

Для проверки настоящего браузерного выбора/перекодирования изображений без записей
в Supabase: `node tests/preview-server.cjs`, затем `http://127.0.0.1:8766`.
Это изолированный стенд с временными данными в памяти страницы: вход допускает
любой тестовый email/пароль и не обращается к настоящему Auth. Настоящие пароли
в нём вводить не нужно. Не публикуйте этот сервер и не меняйте его bind с localhost.

Зависимости используются только для тестов; сайт не требует сборки.
Тесты выполняют миграцию в PostgreSQL через PGlite и проверяют анонимный доступ,
постороннего пользователя, смену учителя, запрет второго учителя и изменение версий.
Отдельно проверяются API-клиент и DOM-интерфейс. Настройку настоящего Supabase Auth
и работу на двух устройствах нужно проверить после создания проекта.

Документация: [Supabase Auth](https://supabase.com/docs/guides/auth/passwords),
[RLS](https://supabase.com/docs/guides/database/postgres/row-level-security),
[ключи API](https://supabase.com/docs/guides/getting-started/api-keys).

## События, новости и мероприятия (11 октября 2026)

### Выпуск v6

1. После двух существующих миграций выполните в SQL Editor
   `supabase/migrations/202610110001_class_events.sql` целиком один раз. Она создаёт
   `public.events`, политики доступа и публичный bucket `event-photos`.
2. Проверьте чтение `events` без входа и запись существующим назначенным учителем.
   Новых аккаунтов, паролей или секретов не требуется.
3. Только после успешной миграции публикуйте клиент v6 на GitHub Pages.
   `schoolTimeZone` в `homework-config.js` задаёт часовой пояс событий
   (по умолчанию `Asia/Yekaterinburg`). Расписание и домашние задания сохраняют свои правила дат.
4. Проверьте на двух устройствах: учитель публикует событие, посетитель без входа
   видит его после обновления. Затем проверьте редактирование, отмену, архив и удаление.
   Окончание проверки — отсутствие ошибок запросов `events`/`event-photos` и корректная
   работа прежних вкладок, в том числе в установленном приложении после обновления.

### Публикация

Откройте «События» → «Учителю», войдите привычным аккаунтом и нажмите
«Добавить публикацию». Выберите мероприятие, контрольную или объявление.
Заполните заголовок и описание; для мероприятия и контрольной нужна дата с годом.
Объявление можно оставить без даты. Поля времени, места, стоимости и условий оплаты
необязательны. Время допускает несколько сеансов: «13:30 — 1 группа; 14:30 — 2 группа».

Можно добавить до четырёх изображений (те же лимиты и форматы, что у домашних заданий).
«Предпросмотр» показывает карточку до отправки. «Опубликовать» загружает изображения
и сохраняет публикацию. До подтверждения сервера сообщение об успехе не появляется.
События, изображения и условия оплаты доступны всем посетителям по ссылке.
Приложение не принимает платежи и не собирает ответы родителей.

Переключение вкладок сохраняет форму. При ошибке или истечении сеанса войдите снова
и повторите отправку: текст и подготовленные фотографии сохраняются в открытой странице.
После закрытия или перезагрузки страницы несохранённая форма теряется; серверных
черновиков нет. После неопределённого результата отправки повтор использует тот же
идентификатор, предотвращая дубликат. Если публикация уже сохранена с иным содержимым,
обновите список и откройте её для редактирования.

### Просмотр и архив

Объявления без даты отображаются от новых к старым; ближайшие события — по дате.
«Подробнее» раскрывает полный текст, оплату и фото. Родителям вход не нужен.
Учитель может редактировать, отменить событие, вручную перенести в архив или удалить.
Отменённое будущее событие остаётся в списке с пометкой. Прошедшая дата переводит
запись в архив на следующий день по времени школы. Возврат из ручного архива не
делает прошедшую дату будущей: для этого отредактируйте дату.

Открытый раздел обновляется каждую минуту, при возвращении в приложение и появлении
сети. Обновление сохраняет раскрытые карточки и загруженные страницы (по 50 записей).
Без интернета доступен последний загруженный текст с датой копии; фотографии могут
быть недоступны. Опубликовать офлайн нельзя. При недоступности событий остальные
разделы продолжают работать.

Фотографии используют отдельное хранилище `event-photos`. Запрет перезаписи и удаления
связанных объектов действует на сервере. При отмене формы и после успешной замены
или удаления публикации клиент очищает неиспользуемые фото. После закрытия вкладки
во время отправки возможны оставшиеся объекты: проверяйте их по `events.photo_paths`
и удаляйте через Storage API/панель, как фотографии заданий. Повтор загрузки после
потери ответа использует прежнее имя; существование объекта проверяется через Storage.

### Проверки и откат

`npm ci && npm test` проверяет модель дат, API, общую сессию, DOM, RLS и Storage-политики.
Для проверки выбора фото, предпросмотра и просмотра во второй вкладке:
`node tests/preview-server.cjs`, затем `http://127.0.0.1:8766`.
Это изолированный стенд: любой тестовый вход, данные событий и фото живут в памяти
локального сервера, домашние задания — в памяти страницы. Перезапуск сервера очищает
события. Он не обращается в настоящий Supabase. Настоящие пароли сюда не вводите.

При откате верните прежние статические файлы с новым номером кэша, оставив таблицу,
bucket и назначение учителя. Старый клиент продолжит работать с домашними заданиями;
публикации сохранятся до возврата интерфейса событий. Не публикуйте повторно старый
номер кэша.
